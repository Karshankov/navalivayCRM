# Нативное приложение CRM для macOS

Отдельное приложение на Tauri 2: своё окно в Dock вместо вкладки браузера и
нативные уведомления, которые приходят, даже когда окно свёрнуто.

Сделано для одного пользователя на своём маке. **Прод, сервер и веб-версия
не затрагиваются:** приложение работает с теми же API и не требует правок
на сервере.

## Зачем своё приложение

| Что нужно | Веб-версия | Это приложение |
|---|---|---|
| Уведомления при свёрнутом окне | не работают | работают |
| Иконка с числом в Dock | нет | есть |
| Своё окно вместо вкладки | нет | есть |

## Как устроено

Главная сложность: фронтенд ходит на **относительные пути** (`/api/...`) —
их больше 320 — и переписывать их нельзя, иначе сломается веб-версия.

Решение: приложение поднимает **свой HTTP-сервер** на `127.0.0.1:47203`,
который раздаёт собранный фронтенд и проксирует `/api` и `/uploads` на
бэкенд. Для окна фронт и API оказываются одним адресом — как за nginx на
проде. Поэтому не мешают ни `sameSite=strict` в куках, ни CORS, ни CSP.

```
окно приложения
      │
      ▼
127.0.0.1:47203  (сервер внутри приложения)
      │  ├── статика  → собранный фронтенд из ../../frontend/dist
      │  └── /api     → backend (по умолчанию https://navalivay.store)
      ▼
  бэкенд CRM
```

### Файлы

| Файл | Зачем |
|---|---|
| `src-tauri/src/lib.rs` | создаёт окно с адресом `/admin`, задаёт масштаб 80% |
| `src-tauri/src/proxy.rs` | сервер: статика + прокси на бэкенд |
| `src-tauri/src/notifications.rs` | мост уведомлений в macOS |
| `src-tauri/capabilities/default.json` | разрешения Tauri для уведомлений и значка |

## Сборка

Нужен Rust: `export PATH="$HOME/.cargo/bin:$PATH"`.

```bash
npm install
npm run sync          # копирует свежий фронтенд из ../frontend/dist
npm run tauri dev     # запуск на разработку
npm run tauri build   # собрать .app и .dmg
```

Готовое приложение появится в
`src-tauri/target/release/bundle/macos/NAVALIVAY CRM.app`.

## Настройки

| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `CRM_BACKEND` | `https://navalivay.store` | какой бэкенд использовать |

Для работы с локальным бэкендом:

```bash
CRM_BACKEND="http://127.0.0.1:3001" ./target/release/crm-app
```

Масштаб интерфейса задаётся константой `ZOOM` в `src-tauri/src/lib.rs`.

## Что важно знать при доработке

**Уведомления перехватываются в окне.** Скрипт из `notifications.rs`
внедряется до загрузки страницы и подменяет `window.Notification`. Благодаря
этому **фронтенд CRM не знает о приложении**: тот же код работает в браузере
и в Telegram. Менять фронтенд под приложение не нужно и не следует.

**Общение идёт через штатный плагин уведомлений.** Свои команды Rust
потребовали бы отдельного объявления в ACL Tauri — на этом легко застрять
(ошибка выглядит как `Command not allowed by ACL`).

**Поток событий требует гипер.** Прокси работает на `hyper`, а не на простых
серверных библиотеках: SSE (живой канбан) не должен буферизоваться. С
буферизующим сервером события приходят пачками с задержкой.

**Для HTTPS нужен `rustls-tls`.** При `reqwest` с `default-features = false`
без него запросы к продакшену падают молча.
